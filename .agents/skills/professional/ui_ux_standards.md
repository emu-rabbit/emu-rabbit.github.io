# UI/UX 與視覺規範 (UI/UX Standards)

## 概述
本技能確保本專案的個人檔案網站具備高品質視覺、清楚敘事、良好互動與跨裝置可用性。它的核心不是套模板，而是讓頁面像被本人細心設計過的「網頁版自我介紹」。

## 觸發條件
- 建立或修改頁面、section、layout、CSS、動畫、字體、色彩、圖片或互動時。
- 撰寫使用者可見文案、導覽、作品描述、關於我內容或聯絡方式時。
- 評估網站是否有模板感、視覺噪音、資訊層級混亂或 mobile/desktop 品質落差時。

## 核心規則

### 體驗定位
- **個人感優先**：頁面應呈現專案擁有者的個性、專業、審美與節奏，不應像通用履歷模板。
- **第一眼要有辨識度**：第一 viewport 應立即讓訪客感受到這是誰、這個人有什麼氣質或專業方向。
- **展示不是堆資料**：作品、技能、經歷與聯絡方式要被編排成有節奏的敘事，而不是單純資料表。
- **靜態也要有設計感**：即使是純靜態頁，也應透過排版、留白、圖像、動線、細節與微互動形成獨特記憶點。

### 視覺設計
- **避免模板感**：不要直接做常見 hero + 三張卡片 + 技能 tag + contact form 的套版結構，除非有明確創意改造。
- **建立視覺系統**：色彩、字體、間距、邊框、陰影、圖案與動效都應有一致規則。
- **主題不單調**：避免整頁只依賴單一色相或常見紫藍漸層、米色履歷風、深藍 dashboard 風。
- **裝飾需有語意**：裝飾元素應服務身份、敘事或動線；若只增加噪音，應刪除。
- **可讀性不可犧牲**：文字對比、行高、段落寬度、按鈕大小與 focus 狀態必須可讀可用。

### 版面與響應式
- **手機與桌面同等優先**：不可只完成桌面後讓手機被動縮放，也不可只為手機犧牲桌面資訊密度與視覺節奏。
- **穩定尺寸**：固定格式元素需有明確 `aspect-ratio`、min/max、grid track 或其他約束，避免 hover、載入或文字長度造成 layout shift。
- **文字不可溢出**：任何 viewport 中，標題、按鈕、卡片與標籤文字都不可互相重疊或超出容器。
- **觸控友善**：行動版互動目標要足夠大，間距要避免誤觸。
- **掃讀效率**：桌面版應保留清楚資訊層級與掃讀路徑，不要把所有資訊壓成手機式單欄。

### 互動與動效
- **微互動要克制**：hover、scroll、cursor、transition 或 canvas 動效應強化個性與理解，不應干擾閱讀。
- **尊重 reduced motion**：動畫需支援 `prefers-reduced-motion` 或提供低動態 fallback。
- **互動可退化**：核心內容與連結在 JavaScript 失效時仍應可讀可用。
- **不要用內部術語當 UI**：使用者可見文案應自然，避免工程狀態名、檔案名或內部分類外露。

### 內容與文案
- **具體勝過泛泛**：避免只寫「熱愛技術、擅長溝通」等模板句，應用具體專業、作品、方法、價值觀或經驗支撐。
- **自我介紹要有聲音**：文案可有個性，但要清楚、真誠、可理解。
- **技能呈現要有上下文**：不要只列 logo 或 tag；需讓訪客知道這些技能如何被使用、解決什麼問題或形成什麼風格。
- **聯絡方式清楚**：訪客想進一步認識或合作時，入口應明確且不突兀。

## 執行步驟
1. 設計前先讀取 `.agents/mission/product_experience.md` 與 `.agents/architecture/technical_architecture.md`。
2. 先定義頁面的敘事節奏：第一眼、身份、作品/能力、個性細節、聯絡或下一步。
3. 建立或沿用視覺 token：色彩、字體、間距、形狀、動效與資產風格。
4. 同時規劃 mobile、tablet、desktop 的資訊順序與布局。
5. 實作後檢查文字、圖片、互動、focus、hover、reduced motion 與不同 viewport。

## 範例
- **正確**：讓 hero、作品呈現、技能區與聯絡入口共享同一套視覺語彙，但各自有清楚節奏。
- **正確**：用自訂排版、局部插圖、細緻 scroll 動效或獨特資訊結構呈現個人風格。
- **錯誤**：複製常見 portfolio template，只替換姓名與作品文字。
- **錯誤**：為了華麗動效導致手機卡頓、文字不可讀或鍵盤無法操作。

## 注意事項
- 本專案可以很有視覺個性，但不可犧牲可讀性、效能、無障礙與內容真實性。
- 若視覺方向需要個人資料、照片、作品或語氣偏好，而 repo 中尚未提供，先用可替換的結構與 placeholder，並清楚標示需要使用者補內容。
