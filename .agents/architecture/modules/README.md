# 模組架構文件維護規則

## 文件目的
本資料夾用來記錄重要頁面區塊、互動系統、資產系統或未來擴充模組的架構邊界。

只有當某個區塊或互動的複雜度足以影響後續維護時，才需要新增模組文件。不要為每個小 section 都建立文件。

## 何時新增模組文件
- 新增複雜作品展示系統。
- 新增自訂動畫、canvas、WebGL 或互動實驗。
- 新增多頁結構、資料檔或內容生成流程。
- 新增可替換視覺主題、資產 pipeline 或字體策略。
- 新增會影響效能、可及性、部署或長期維護的模組。

## 命名規則
- 使用小寫英文與 hyphen，例如 `project-gallery.md`、`visual-system.md`。
- 文件標題使用清楚中文名稱。
- 若只是模板，保留 `_module_architecture_template.md` 前綴底線。

## 維護規則
- 模組文件應記錄長期有用的邊界、取捨、資料結構、資產策略、驗證方式與待決策事項。
- 不要把一次性修 bug、短期 TODO 或聊天摘要放進模組文件。
- 若模組決策有重要取捨理由，依 `.agents/skills/core/decision_traceability.md` 判斷是否同步到 decision history。
