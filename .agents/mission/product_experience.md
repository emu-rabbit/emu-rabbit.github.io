# emu-rabbit.github.io 產品體驗方向

## 體驗目標
本網站應像一個被精心設計過的個人入口：輕、快、可讀，但有明顯的個性與記憶點。它可以有藝術感、技術感、可愛感、實驗感或其他專案擁有者偏好的方向，但不應落入通用履歷模板或常見 portfolio clone。

UI/UX 的核心目標是：在保有可用性、可維護性與內容清楚的前提下，讓頁面具有獨特設計感與個人聲音。

目前已確認的品牌氛圍應偏向溫柔、自由、舒適、親人、坦白而帶一點可愛感。它可以有夜色、兔子、手寫日記、窗光、花草、柔焦材質與生活感；不應像商業簡報、企業履歷、SaaS 首頁、資料圖表或冷調 dashboard。

## 跨裝置體驗
手機版與桌面版都必須是第一級目標。Agent 建立或修改任何畫面時，不應只完成桌面版後讓手機被動縮放，也不應只做手機版而犧牲桌面掃讀效率與視覺層級。

可接受的是「不同裝置有不同節奏」；不可接受的是「某一種裝置只是勉強不壞」。

背景圖與首屏尤其要分別考慮桌機與手機構圖。若使用大型氛圍圖，應優先準備桌機橫式與手機直式版本，並控制檔案大小；不可只用單一大圖裁切到手機後才檢查可讀性。

整頁背景採窗邊手記式分層策略：首屏與少數關鍵段落可以是具象場景，中後段應以章節色溫、手記材質、相簿感、路徑線條與既有圖片建立節奏。不要為每個 section 都新增 full-bleed AI 大圖，也不要讓同一張背景無差別固定覆蓋整頁到失去段落分隔。

## 視覺方向
- 高度客製、具辨識度，不像模板換字。
- 可使用插圖、照片、材質、排版實驗、局部動效或互動細節建立個性。
- 裝飾不可搶走主體內容，也不可降低文字可讀性。
- 不要做成 generic dashboard、SaaS landing page、制式履歷或卡片堆疊模板。
- 靜態頁也應有完整視覺系統，而不是零散裝飾。
- 避免會讓人聯想到數據、圖表、KPI 或儀表板的橘藍長條、刻度、數字裝飾與資訊圖表語彙，除非任務本身真的在呈現資料。
- 後續區塊背景應像同一本手記的不同頁面：彼此共享色彩、字體、柔和夜色與兔子語氣，但透過材質、光線方向、分隔線與少量語意圖形建立章節差異。
- 新增大圖前需先確認其敘事角色、手機/桌機構圖、壓縮策略與是否值得增加載入成本；若只是補氛圍，優先使用 CSS 材質或現有資產。

## 互動方向
- 核心內容應快速出現，不因動畫或 loading 儀式被延遲。
- 動效應增加細膩感、引導視線或表達個性，不應干擾閱讀。
- 所有互動都需要鍵盤與觸控可用。
- 支援 reduced motion，並避免在低效能裝置上造成卡頓。
- 連結、按鈕、作品 preview 與外部入口應有清楚狀態。

## 內容語氣
適合的語氣：

- 具體
- 真誠
- 有個性
- 好讀
- 有設計感但不炫技

不適合的語氣：

- 過度商業化
- 模板式自我稱讚
- 空泛技能羅列
- 把工程內部命名直接暴露給訪客
- 為了酷而讓內容難以理解

## 設計判斷準則
當 Agent 需要做 UI、流程或文案取捨時，應優先檢查：

1. 這個設計是否讓訪客更理解專案擁有者？
2. 它是否看起來像獨立設計，而不是套版？
3. 它是否維持輕量、快速、靜態友善？
4. 它是否在手機與桌面都自然可用？
5. 它是否讓重要內容更清楚，而不是被裝飾蓋過？
6. 它是否方便未來更新作品、文案與視覺細節？

若以上方向與技術便利性衝突，Agent 應回到專案使命與使用者需求判斷；若仍不明確，先詢問使用者。
