# emu-rabbit.github.io 功能版圖

## 產品範圍觀
本文件描述目前已知的功能方向，但不是封閉需求清單。Agent 應把本專案視為一個可持續調整的個人展示頁，而不是一次性丟棄的靜態模板。

每個功能都應服務「讓訪客理解專案擁有者」這個核心目標。

## 已知功能方向

### 首屏身份展示
首屏負責建立第一印象：姓名或識別、短句、視覺語氣、主要專業方向與下一步入口。

設計時應注意：

- 第一眼要有個人辨識度，不只是大標題加按鈕。
- 不應讓背景或裝飾遮蔽關鍵文字。
- 首屏應暗示下方仍有內容，避免像封閉海報。
- 手機與桌面可採不同布局，但身份訊號必須同樣清楚。

### 自我介紹與價值觀
自我介紹區塊負責讓訪客理解專案擁有者的工作方式、思考方式、偏好與個性。

設計時應注意：

- 避免空泛模板句。
- 可用短段落、時間線、關鍵句、互動細節或特殊排版呈現。
- 內容應自然、真誠、具體。

### 生活照與個人氛圍
生活照區塊用來補足本人日常、穿搭、用餐、外出與被觀看時的親近感，讓網站不只像文字自介，也像可以慢慢靠近的一本生活手記。

設計時應注意：

- 照片呈現應保留人物清晰度與生活感，不應過度遮罩、霧化或裁切到失去主體。
- 圖片輪播、滑動或選擇控制應保持手動可操作，並能在 JavaScript 失效時退回為可閱讀的靜態照片列。
- 圖片資產需有清楚命名、尺寸資訊、替代文字與穩定版面，避免載入時造成明顯跳動。
- 文案語氣可以親密可愛，但仍需尊重本人主體，不要變成模板式相簿說明。

### 專業技能與領域
技能區塊用來展示專業能力，但不應只是堆疊技術 tag。

設計時應注意：

- 技能要與實際作品、經驗或解決問題方式連結。
- 可依「能力型態」分類，例如設計、前端、資料、工具、寫作、社群、研究等。
- 若尚未有完整資料，使用清楚 placeholder，不要臆造經歷。

### 作品與專案展示
作品區塊用來展示專案、案例、實驗、文章或其他可被訪客理解的成果。

設計時應注意：

- 每個作品應有清楚名稱、角色、脈絡、成果與連結。
- 不需要大量卡片；少量但有敘事的展示更符合個人網站。
- 作品截圖、影片或互動 preview 應壓縮且可替代。

### 聯絡與外部連結
聯絡區塊提供訪客下一步行動，例如 GitHub、社群、Email、作品集連結或其他公開身份。

設計時應注意：

- 入口清楚但不應像強銷轉換漏斗。
- 外部連結需要可辨識 label 與可用的 focus/hover 狀態。
- 若某些聯絡資訊尚未確認，不要假造。

### 視覺系統與靜態資產
本專案的視覺系統本身就是核心功能之一。

設計時應注意：

- 圖像、字體、色彩、動效與版面都需服務個人身份。
- 靜態資產應有清楚命名與資料夾結構。
- 圖片、字體與動畫不可讓頁面變重或難以維護。
- 目前背景資產需保留桌機橫式與手機直式版本，並控制檔案大小，避免為了氛圍犧牲載入速度。
- 品牌 icon 應維持黑夜底白兔、柔和光暈與手作感，不使用容易聯想到圖表、數字、KPI 或 dashboard 的長條裝飾。

## 擴充原則
未來可能增加文章、作品詳情頁、互動實驗、語言切換或下載版履歷。Agent 在設計檔案結構與 UI 時，應避免把網站寫死成完全不可延伸的單頁臨時稿，但也不可為未確認需求過度設計。

好的方向：

- 內容資料與呈現結構清楚分離。
- 靜態資產路徑與命名可維護。
- 可以新增 section 或頁面而不重寫整站。
- CSS token 可支援後續風格調整。
- 互動效果可退化、可移除、可測試。

應避免：

- 為了未確認功能導入 CMS、資料庫或大型 framework。
- 把所有內容硬塞進一個難以讀懂的巨大檔案。
- 用模板式卡片填滿頁面。
- 用過重動畫或圖片犧牲載入速度與可讀性。
