# emu-rabbit.github.io 專案使命

## 專案名稱
- Repository：`emu-rabbit.github.io`
- 暫定定位：個人檔案與自我介紹靜態網站

## 核心定位
本專案是一個非常輕量化的靜態網頁，用來展示專案擁有者的個人檔案、自我介紹、專業能力、作品與可被理解的個人風格。

它不是一般履歷模板、不是通用 SaaS landing page，也不是需要後台管理的內容系統。它應該被理解為「高度客製化的網頁版自我介紹」：內容、排版、視覺、互動與動線都要服務於專案擁有者的真實身份與想被看見的方式。

## 成功標準
本專案成功時，訪客應能快速感受到：

- 這個人是誰。
- 他的專業領域、作品方向或思考方式是什麼。
- 這個網站具有明確個性，而非模板換皮。
- 網站輕量、快速、好讀，並在手機與桌面上都完整。
- 若想進一步認識、合作或聯絡，路徑清楚。

## 設計與維護價值
Agent 在做任何產品、文件、UI 或架構判斷時，應優先對齊以下方向：

- **個人化**：設計與文案應回到專案擁有者，而非抽象市場受眾。
- **輕量化**：技術、依賴與資產都應保持簡潔，避免為一頁展示站加入不必要重量。
- **高客製**：可以有獨特視覺語言、互動、排版與敘事，不追求套版效率。
- **可維護**：未來更新作品、文字、連結與視覺細節時，檔案結構應清楚。
- **跨裝置品質**：手機、平板與桌面都需被當成正式展示面。
- **內容真實**：不要用空泛形容詞填滿頁面；作品、技能與自我描述要可被具體理解。
- **親近氛圍**：品牌感應溫柔、自由、舒適、親人，像可以靠近的一扇窗，而不是商業履歷、冷冰冰專業名片或資料儀表板。
- **雙版面意識**：桌機與手機的背景、首屏、閱讀節奏與留白都需個別設計與驗證；不可把手機版當成桌機裁切或被動縮放的副產品。

## 非目標
- 不做需要登入、後台、資料庫或私密權限模型的系統。
- 不建立沉重 CMS、部落格平台或多使用者產品，除非使用者另行確認。
- 不把本網站做成模板履歷、通用 portfolio clone 或企業式 landing page。
- 不為未確認的未來功能提前導入大型框架、狀態管理或複雜建置流程。
- 不搬入 `freezer_space` 的產品使命、關係脈絡、Flutter/Firebase 架構或私密生活工具功能。

## 長期方向
本網站可以隨著專案擁有者的作品、身份與審美持續演化。後續新增區塊或互動時，應保留輕量、可部署、好維護的基礎，同時讓視覺語言越來越貼近本人，而不是越來越像泛用模板。
